# 冲刺测试夹具与补测

最终包首次 `r6a` 在一个会话连续执行 TP/FP 各七类、每类十次。角色原生弹药只有弹匣 12 + 备用 48；测试只请求正常装弹，没有凭空补弹。因此 TP 腰射中途耗尽全部 60 发，FP 腰射零实际发射，后续装弹也未开始。40 条装弹断言 FAIL 原样保留，不能用其速度断言通过来代替有效射击验收。

补测仍使用同一个最终 Shipping EXE 的既有 `r6apilot` 入口，每次独立用户目录和独立会话。每次运行 TP/FP 各一轮七类，总共十个会话。每个会话最多 22 发，原生初始弹药够用，既不改伤害、冷却，也不改包或注入弹药。按十个完成会话汇总才构成每项十次的有效结果；未完成时不提前记 PASS。

原始结果保留在 `FINAL_RESULTS.json` 的 `sprint` / `sprint_trials`；补测单独列 `fresh_sprint` / `fresh_sprint_trials`。正式验收以真实发射次数、动作帧存在和状态恢复共同判断。`hits` 是目标健康下降事件次数，不是三连段命中率；一段可能无目标或目标已离开够及范围。

所有数值来自引擎动作与真实角色速度采样（B 动作 + A 读取），不是人工操作。C-OS 另行记录。`max_hit_window_recovery_s` 保留每次窗口关闭后的恢复，包括跨越下一段的情况，不得只报最后一击的收招值。

逐帧复核发现 TP 拳命中后的一个真实边界问题：约 0.31667 秒窗口关闭，至约 1.05 秒才到 650，最差约 0.733 秒。源码 `SweepPunch` 命中后会 `Montage_Stop(.08f,ActiveMontage)`；`GetAttackAnimationElapsed` 因动画不再播放返回 -1，而 R6 速度计算仍把 -1 判在窗口末尾之前，维持 552.5。这说明本轮“最终动作结束恢复”断言不够严格，0.2 秒窗口要求不能记为全面 PASS。源包已冻结，完整回归已执行一次；在未经用户追加授权前，不私自改包后再重复完整回归。
